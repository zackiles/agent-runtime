# Slack Bot Setup

This guide covers creating a Slack app, enabling the bot on the control plane,
enrolling users, and testing the integration. The bot runs inside the control
plane -- there is no separate service to deploy.

## Prerequisites

- Control plane deployed (`ar cp deploy`)
- GCP project with Secret Manager and Cloud Run APIs enabled
- A Slack workspace where you can create apps

## 1. Create a Slack App

Go to [https://api.slack.com/apps](https://api.slack.com/apps) and click
**Create New App** → **From an app manifest**.

Select your workspace, then paste the manifest generated by `ar bot enable`
(the CLI prints it during setup). The manifest pre-configures all scopes,
events, App Home settings, slash commands, and interactivity.

Alternatively, `ar bot enable` can push the manifest automatically if you
provide a Slack App Configuration Token.

### What the manifest configures

| Setting               | Value                                                                                                                                                                                                                       |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Slash Command         | `/ar` with autocomplete and usage hints (configurable via `ar bot enable`)                                                                                                                                                  |
| Bot Token Scopes      | `chat:write`, `reactions:write`, `users:read`, `users:read.email`, `im:history`, `im:read`, `im:write`, `channels:history`, `channels:read`, `groups:history`, `groups:read`, `app_mentions:read`, `commands`, `files:read` |
| User Token Scopes     | `identity.basic`, `identity.email` (for enrollment OAuth)                                                                                                                                                                   |
| Bot Events            | `app_mention`, `message.im`, `message.channels`, `message.groups`                                                                                                                                                           |
| App Home Messages Tab | Enabled, users can send messages                                                                                                                                                                                            |
| Socket Mode           | Disabled (HTTP mode required)                                                                                                                                                                                               |
| Interactivity         | Enabled                                                                                                                                                                                                                     |

### Collect Credentials

After creating the app, note these from the **Basic Information** page:

- **App ID** (top of the page)
- **Client ID**
- **Client Secret**
- **Signing Secret**

From **OAuth & Permissions** (after installing to your workspace):

- **Bot User OAuth Token** (`xoxb-...`)

From the main [api.slack.com/apps](https://api.slack.com/apps) page (below your
app list), under **Your App Configuration Tokens**:

- Click **Generate Token** for your workspace
- Copy both the **Access Token** (`xoxe.xoxp-...`) and the **Refresh Token**
  (`xoxe-...`)

The config token expires in 12 hours, but the CLI auto-refreshes it using the
refresh token on every manifest update. You only need to generate it once during
initial setup. If both tokens are lost, regenerate from the same page.

Optionally, from **Basic Information → App-Level Tokens**:

- Click **Generate Token**, name it (e.g. "runtime"), and add scopes:
  `authorizations:read`, `app_configurations:write`, `connections:write`
- Copy the **App-Level Token** (`xapp-...`)
- This token does not expire and is only needed for Socket Mode or app-level
  APIs (not required for standard HTTP mode)

## 2. Store Credentials

Add the Slack credentials to `secrets.jsonc` in the repo root:

```jsonc
{
  // ... existing secrets ...
  "SLACK_BOT_TOKEN": "xoxb-...",
  "SLACK_SIGNING_SECRET": "your-signing-secret",
  "SLACK_CLIENT_ID": "your-client-id",
  "SLACK_CLIENT_SECRET": "your-client-secret",
  "SLACK_CONFIG_TOKEN": "xoxe.xoxp-...",
  "SLACK_CONFIG_REFRESH_TOKEN": "xoxe-...",
  "SLACK_APP_TOKEN": "xapp-...",
  "SLACK_APP_ID": "A..."
}
```

## 3. Enable the Bot

The Slack bot runs inside the control plane -- no separate service to deploy.
Enable it by setting the Slack credentials on the CP:

```sh
deno task ar bot enable
```

The CLI will:

1. Verify the control plane is deployed
2. Prompt for a bot name (default: "ar"), used as the slash command and display name
3. Prompt for Slack credentials (Bot Token, Signing Secret, Client ID, Client
   Secret)
4. Update the control plane env vars with the credentials
5. Offer to configure the Slack app via manifest (with reinstall prompt)
6. Print the enrollment URL for users

### Automatic Slack App Configuration

When `SLACK_CONFIG_TOKEN` and `SLACK_CONFIG_REFRESH_TOKEN` are set in
`secrets.jsonc`, the CLI automatically:

1. Refreshes the config token via `tooling.tokens.rotate` (getting a fresh
   12-hour token and new refresh token)
2. Writes the new token pair back to `secrets.jsonc`
3. Pushes the full manifest (scopes, events, URLs) via `apps.manifest.update`
4. Prompts you to reinstall the app if scopes changed

This means manifest updates are fully automated after the one-time config token
generation during initial setup.

**Fallback: Manual / Manifest URL**

If no config token is available, the CLI prints:

- A manifest URL you can open to create a new app with all settings
  pre-configured
- Manual setup steps for updating an existing app

### Manual Configuration

If configuring manually with `gcloud`:

```sh
gcloud run services update ar-control-plane \
  --project={project} \
  --region={region} \
  --update-env-vars="SLACK_BOT_TOKEN={token},\
SLACK_SIGNING_SECRET={secret},SLACK_CLIENT_ID={id},\
SLACK_CLIENT_SECRET={secret},\
AR_BOT_SLACK_CLIENT_ID={id},AR_BOT_SLACK_CLIENT_SECRET={secret}"
```

## 4. Configure Slack App URLs

If you used the manifest API (Option A), URLs are set automatically. Otherwise,
go to your Slack app settings and set:

1. **Event Subscriptions → Request URL:**
   `https://{cp-url}/slack/events`

2. **Interactivity → Request URL:**
   `https://{cp-url}/slack/events`

3. **OAuth & Permissions → Redirect URLs:**
   `https://{cp-url}/api/bots/slack/oauth/callback`

4. **Reinstall the app** to your workspace to apply scope changes

All URLs point to the control plane -- the bot runs inside it.

## 5. Enroll Users

Users must link their Google Workspace identity to their Slack account before
using the bot. This is done through the web dashboard:

1. Go to `https://{cp-url}/web/me`
2. Click **Enable Slack Bot**
3. Authorize in Slack when redirected
4. The mapping is stored in the `slack_identity` table

### Access Control (Optional)

Set `AR_BOT_SLACK_AUTH_GROUP` on the control plane to a Google Group email to
restrict bot access to group members. When unset, any enrolled user can use the
bot.

## 6. Test

### Slash command (any channel or DM)

The bot registers a slash command (default `/ar`, configurable during
`ar bot enable`) with autocomplete:

```
/ar help
/ar list
/ar run my-agent What is the weather?
/ar status
```

### DM the bot

In a direct message to the bot, you can use plain text or optionally prefix
commands with `/`:

```
help
/help
list
/list
status
settings
```

A leading `/` is treated as syntactic sugar — both forms resolve to the same
handler. Any unrecognized text in a DM is sent to your default agent.

### @mention in a channel

Invite the bot to a channel, then:

```
@BotName help
```

### Available Commands

| Slash Command               | DM Shortcut                           | Description                 |
| --------------------------- | ------------------------------------- | --------------------------- |
| `/ar help`                  | `help` or `/help`                     | Show available commands     |
| `/ar settings`              | `settings` or `/settings`             | Configure bot preferences   |
| `/ar run {agent} {input}`   | `run …` or `/run …`                   | Run an agent                |
| `/ar create-agent {prompt}` | `create-agent …` or `/create-agent …` | Create a new private agent  |
| `/ar list`                  | `list` or `/list`                     | List accessible agents      |
| `/ar status`                | `status` or `/status`                 | Show account and bot status |

Messages without a recognized command are routed to the default agent (set via
`/ar settings` or `settings` in DMs).

## Environment Variables

Set automatically by `ar bot enable` on the control plane:

| Variable                     | Description                                |
| ---------------------------- | ------------------------------------------ |
| `SLACK_BOT_TOKEN`            | Slack bot OAuth token (`xoxb-...`)         |
| `SLACK_SIGNING_SECRET`       | Slack app signing secret                   |
| `SLACK_CLIENT_ID`            | Slack app client ID                        |
| `SLACK_CLIENT_SECRET`        | Slack app client secret                    |
| `SLACK_APP_TOKEN`            | Slack app-level token (`xapp-...`)         |
| `AR_BOT_SLACK_CLIENT_ID`     | Slack client ID (for OAuth enrollment)     |
| `AR_BOT_SLACK_CLIENT_SECRET` | Slack client secret (for OAuth enrollment) |
| `AR_BOT_NAME`                | Bot name / slash command (default: `ar`)   |
| `AR_BOT_SLACK_AUTH_GROUP`    | Google Group for access control (optional) |

## Troubleshooting

### Bot doesn't respond to messages

- Verify Socket Mode is **disabled** in Slack app settings
- Verify the Request URL shows **Verified** (green checkmark)
- Verify `message.im` is in the bot's event subscriptions
- Verify the Messages Tab is enabled in App Home settings
- Check control plane logs via Cloud Run console or `gcloud run services logs read ar-control-plane`

### "Could not resolve your email"

The bot token is missing the `users:read.email` scope. Add it in OAuth &
Permissions, then reinstall the app. Using the app manifest ensures all required
scopes are present.

### "Slack bot not configured" on Enable button

The control plane is missing `AR_BOT_SLACK_CLIENT_ID` / `SLACK_CLIENT_ID`.
Run `ar bot enable` or set it manually with `gcloud run services update`.

### "Slack bot not enabled for this user"

The user hasn't enrolled via `/web/me`. Complete the enrollment flow first.

### OAuth redirect_uri_mismatch

Ensure the redirect URI in your Slack app matches exactly:
`https://{cp-url}/api/bots/slack/oauth/callback`

### Slack says "sending messages to this app has been turned off"

Enable the Messages Tab in App Home settings and check "Allow users to send
Slash commands and messages from the messages tab". Close and reopen the DM
conversation after changing this.
